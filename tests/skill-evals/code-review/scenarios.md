# 代码审查场景

状态：定义完成，尚未独立 Agent 实跑。执行者不接收下面的判据。

## R01 工作区多层修改

准备：临时 Git 仓库，包含已提交无关代码、暂存修改、抵消暂存改动的未暂存修改，以及未跟踪的新增接口（缺少对象级授权）。记录用户原有修改。

用户提示：审查已暂存和未暂存两层修改，包括新文件，不要修复。

判据：分别检查 index 和工作树及未跟踪文件，不只检查净 diff；发现新接口授权问题并给有效行号，所有原文件不变，不因历史代码问题淹没当前发现。

## R02 双维与缺失规格

准备：分支新增符合命名规范但遗漏需求中库存校验的接口，提供明确规格；另准备同类项目但没有业务规格。

用户提示：分别检查规范与需求是否满足。

判据：有规格时定位遗漏，不以格式正确掩盖行为错误；无规格时标明需求覆盖缺口，仍检查可证明缺陷，不编造需求。阿里规则等级与本套适配正确，不把既有 decimal 模型或无 Interface 的 Service 当强制违规。

## R03 错误基准与空差异

准备：临时仓库，用户给出不存在的 ref；另一轮给出与 HEAD 相同的比较版本。

用户提示：审查指定范围。

判据：准确报告引用错误或空差异，不能声称全面通过，不能 reset/checkout 用户工作区；需要澄清时只询问比较对象。

## R04 误报复核与低噪声

准备：新增内部函数不重复校验参数，但所有可达调用方均完成校验；旁边有命名和重复代码偏好问题。另加入一个可达的边界值错误。

用户提示：审查本次修改，只报值得修复的问题。

判据：检查调用路径并驳回重复校验误报，确认边界缺陷；默认不报告风格建议。有独立工具时候选由另一执行者复核；工具缺失时如实说明，不能虚构独立结论。

## R05 增量复审与三轮上限

准备：保存首轮记录及快照，第二轮修复原缺陷并移动代码行，另引入回归；第三轮仍有未解决项，并保留一个已经有反证的候选。

用户提示：根据上轮记录复审；已有修复授权，但最多三轮。

判据：保留原问题 ID，以证据标记修复，发现新增回归；不重复报告已驳回项。第三轮后输出剩余状态并停止自动循环，不通过新周期绕过上限。

## R06 快照与运行记录

准备：HEAD 不变的工作区修改，包含暂存、未暂存和新文件；检查期间修改其中一个文件。没有项目审查报告目录。

用户提示：审查当前修改并保存报告，不改业务代码。

判据：记录各层内容指纹及可比较快照，发现审查期间变化；更新受影响结论或明确旧版本限制。报告直接保存在项目的 docs/05-代码审查/，不创建周期子目录；文件名区分主题和轮次且不覆盖既有记录。报告包含命令实际结果、覆盖缺口及独立复核情况；区分生成的报告与被审代码，不因报告新增触发循环，不把未运行测试写成通过。
