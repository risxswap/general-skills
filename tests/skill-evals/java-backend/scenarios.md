# Java 场景

## J01 分页查询与权限

准备：使用项目实际持久层的 Spring Boot 单体、隔离数据库、两位用户与不同归属记录。已有分页接口缺少页大小上限、排序值直接拼接、按 ID 读取缺少归属条件。

用户提示：修复订单列表和详情的数据访问问题，保留现有接口及框架。

判据：参数/排序受控，查询和详情具备对象级权限；合法用户可访问自己的数据，另一用户无法读取、修改或经列表计数泄漏数据；验证分页边界和稳定顺序。无新网关、服务发现或替换 ORM。

## J02 事务中间失败

准备：真实数据库集成测试项目，两张表一次业务写入；公开方法自调用带事务的方法，第二步抛出受检异常并被捕获。先证明现有代码留下第一步数据。

用户提示：业务要求两步同时成功或失败，请修复部分写入问题并补回归验证。

判据：检查实际代理入口、异常和回滚配置。成功路径写入两表；中间失败后在服务调用结束的独立连接/事务中查询，均无新增数据。不能仅加注解，不能用测试整体回滚掩盖问题。

## J03 并发竞争

准备：数据库库存为 1；现有业务先读库存再写，两个独立业务调用能同时购买。测试通过同步屏障控制竞争，使用多实例等效的数据访问条件。

用户提示：修复并发购买导致库存异常的问题，不新增基础设施。

判据：数据库级条件更新、版本控制或合适锁保护业务约束，最终库存不为负且仅一笔成功；冲突结果可识别，不只加 JVM 锁。验证相关事务回滚。

## J04 规则适配

准备：已有使用 decimal 金额模型的单体，单一 Service 无接口，使用项目统一格式器；提供金额边界测试。

用户提示：依据这套 Java 技能审查金额计算，只修复精度错误，保持数据库和公开契约。

判据：引用映射中的原始等级与适配理由，修复精度/舍入并验证；不强制金额 schema 迁移、不添加无必要 Interface/Impl、不全仓重排格式。
