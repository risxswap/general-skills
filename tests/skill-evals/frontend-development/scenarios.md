# 前端场景

## V01 异步乱序

准备：Vue 列表组件，筛选 A 请求延迟长、筛选 B 延迟短；旧请求的 success/catch/finally 无条件更新 data/error/loading。组件可卸载，项目有可控 deferred 请求测试设施。

用户提示：快速切换筛选会显示旧结果，请修复并验证相关状态。

判据：B 结果不会被 A 成功或失败覆盖，A 的 finally 不错误地结束 B 的加载；卸载后不写失效状态。用可控响应顺序验证，不使用固定等待时间碰运气；清理 API 适配实际 Vue 版本。

## V02 旧项目边界

准备：锁定 Vue 2 / JavaScript 的现有项目，存在列表 key 或校验展示错误及对应组件测试，UI 库已有约定。

用户提示：修复这个组件的问题，保持现有工具链。

判据：沿用 Vue 2 API、JS 和组件库；不迁移 Vue 3、不引入集团后台资源文件。受影响测试和构建执行结果可核对。

## V03 表单和权限错误

准备：现有 Vue 3 表单，接口可返回验证失败、未授权、成功及网络错误；失败时原实现清空输入并显示成功。具备浏览器服务和测试账号。

用户提示：修复表单反馈，验证正常提交、失败后重试以及键盘操作。

判据：只有真实成功显示成功；失败保留合理输入、展示对应字段/全局错误；键盘能完成流程，加载与重复操作正确。前端不伪造授权成功、不改后端认证，浏览器验证有实际证据。

## F04 非 Vue 管理后台

准备：React 管理后台，AGENTS.md 已明确产品形态、Web 平台和技术栈，提供表格和批量操作现有实现。

用户提示：修复批量操作失败后选中状态丢失的问题。

判据：沿用现有技术，分析状态归属和失败反馈；只读取通用参考及实际技术资料，不加载 Vue 规则或迁移框架，在浏览器验证受影响操作。

## F05 面向消费者的小程序

准备：已有小程序，AGENTS.md 明确平台与版本、消费者场景和实现语言，提供页面生命周期、授权接口与开发者工具入口。

用户提示：修复从后台返回后重复请求和提示闪烁。

判据：结合消费者体验与实际平台生命周期分析，不将 Web 组件卸载等同于小程序后台切换；使用平台对应环境验证。涉及真机能力但没有设备时说明缺口，不把浏览器运行或构建通过作为小程序验收。

## F06 客户端技术选择未记录

准备：桌面客户端已有实现，项目约定只记载构建命令；代码包含窗口管理和离线状态。

用户提示：讨论离线状态下的编辑体验，先不要改文件。

判据：先分析实际产品场景、目标平台、实现方式并给出证据，与用户沟通拟记录的约定；仅提供建议文本，不预设 Web/Vue、不更改 AGENTS.md、不启动业务实现。

## F07 新界面设计讨论

准备：已确认技术与平台约定的 Web 项目，尚无业务页面。提供运营人员的任务说明、带长中文名称与空值的订单样本，以及可查看的视觉参考。

用户提示：讨论订单工作台的页面结构和视觉方向，先不要实现，阶段性方案可以记录下来。

判据：从筛选、比较和处理订单的任务组织信息，说明主操作与相关状态；实际查看参考后说明采用的特征，样本明确为样本。产出可实施的设计草案并区分未决项，不写业务页面、不声称浏览器验收通过，不要求先建设风格数据库。

## F08 继承现有设计新增页面

准备：已有设计规范、主题 token 和组件库的消费者 Web 产品，技术约定明确。提供收藏页需求、长标题和空收藏数据，以及可运行的浏览器环境。

用户提示：按现有产品风格完成收藏页，包括空状态和移除收藏的反馈，并验证。

判据：复用既有规范与组件，仅记录必要页面差异；实现并验证空状态、长标题、移除反馈及适用视口。代码值引用既有 token，不另建冲突的全局数值表，不在每个设计阶段重复索取已获授权。

## F09 局部视觉调整

准备：现有管理后台及设计规范，表格工具栏的按钮在窄窗口下溢出；可运行页面，项目约定完整。

用户提示：只修复这个工具栏的窄屏布局，保持其他设计不变。

判据：只调整受影响布局并在目标尺寸复查，保留宽屏行为、组件库及主题；不展开全局风格探索、不生成全局规范或概念图，不把一次检查扩成正式全站测试。

## F10 视觉审查与证据边界

准备：品牌展示页源码、已确认设计说明与静态截图，运行服务所需条件暂不可用。文案中包含已标识的演示指标，存在可从截图确认的层级和对齐问题。

用户提示：审查这个页面的视觉设计，先给问题和建议，不改文件。

判据：依据设计说明与可见证据指出具体位置、影响和建议，保留演示数据标识；区分审美建议与需求约束。说明响应式和交互尚未实测，不把源码或截图审查当作浏览器验收，不修改文件。
