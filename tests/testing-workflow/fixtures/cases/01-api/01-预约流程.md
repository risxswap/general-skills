# 预约流程

[[docs/testing/01-cases/01-api/00-接口测试用例|返回接口测试用例]]

## 公共准备

- 测试会议室：青山会议室，处于启用状态。
- 预约日期：用例开始时按 Asia/Shanghai 时区确定的明天。

## 用例

### API-BOOK-010｜两人争抢同一时段仅一人成功

用例编号：API-BOOK-010 ^case-api-book-010

优先级：P0
状态：可执行
关联需求：REQ-BOOK-001、REQ-BOOK-002
关联风险：RISK-BOOK-001、RISK-BOOK-002
关联接口：createBooking

#### 准备

- 满足“公共准备”。
- 两个独立员工会话已登录；「测试会议室」在「预约日期」10:00—11:00 没有预约。
- 各账号使用独立凭据，记录测试前预约数量。

#### 数据

- 时段：10:00—11:00。
- 会议主题：并发预约验证。

#### 步骤

1. 并发提交
   操作：通过接口 createBooking，以两个员工会话对「测试会议室」的「预约日期」「时段」提交主题为「会议主题」的请求。
   并发：两个会话在发送前同步屏障汇合，同时释放；每个会话仅提交一次，不自动重试；等待两份响应。
   等待：依测试环境接口时限最多等待 5 秒，超时保留请求记录并判为失败。
   检查：
   - 两份响应恰有一份状态码为 201，另一份为 409。
   保存为：成功预约编号 ← 状态码为 201 的响应体 id。

2. 核实持久化
   操作：通过公开查询接口读取「成功预约编号」。
   检查：
   - 查询返回 200，会议室和时段与提交值相同。

#### 最终检查

- 通过公开接口查询，目标时段新增预约数量恰为 1；保存两份请求与响应及查询结果作为证据。

#### 清理

- 在测试环境取消「成功预约编号」，保留脱敏证据；若未产生编号则仅记录无需取消。
