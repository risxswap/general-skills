# 打包与安装

## 已确定范围

提供 Go CLI 与离线发布包，场景、项目目录及用户级范围由用户指定，不探测业务项目。首版按 Codex 当前 `.agents/skills` 本地发现路径安装；没有联网更新或管理员级安装。

通用开发包含 development-workflow（含领域建模和技术设计）、diagnosing-bugs、code-review、humanizer-zh，共 4 个技能。测试技能组包含 testing-workflow、api-testing、ui-testing，共 3 个技能，始终一起安装。

场景定义以 `tools/internal/kit/bundle.go` 为单一来源：`general` 为通用开发（4 个），`java` 为通用开发 + Java 后端 + 测试技能组（8 个），`frontend` 为通用开发 + 前端开发 + 测试技能组（8 个），`fullstack` 为全部技能（9 个），`testing` 为专项测试，仅安装测试技能组（3 个）。发布包仍包含全部技能，用户无需手动补依赖。`general` 不再安装测试技能组，但不会删除已有安装中的测试技能；可另选 `testing` 补充测试能力。

公共入口对 Java 后端与前端 使用名称定位并先检查存在，避免可选路由成为缺失文件链接。打包会对每个场景检查实际 Markdown 文件链接，缺少必需参考即失败。当前链接检查支持本仓库的无空格内联文件链接，忽略 fenced 代码与外链，不校验锚点或执行自然语言引用。

## 格式与验证

技能 ZIP 根文件 `manifest.json` 含格式版本、发行版本和每个技能文件的 SHA-256，文件位于 `skills/<name>/...`。安装先完整验证包，再写入目标。校验用于发现损坏，不是数字签名或发布者身份认证。

包只接受普通文件及可跨平台的 ASCII 文件名，拒绝符号链接、重复路径、越界路径、Windows 保留名称和超限内容；单文件上限 8 MiB，展开总量 64 MiB。新增资源超出当前能力时修改格式和测试，不静默跳过。安装文件权限为 0644；测试工作流的 Python 脚本通过 `python3` 调用，无需可执行位。脚本自测和中文路径夹具位于仓库 `tests/testing-workflow/`，不进入发布包。若以后需要直接执行脚本，再扩展权限元数据。

打包入口：根目录 package.sh；Go 模块：tools。默认仅构建 darwin/arm64，输出到 dist/，按平台命名安装目录与 ZIP，不增加版本目录或版本文件名；保留压缩前的完整安装目录。`package.sh` 在使用默认 `dist/` 时会先清空旧产物，便于重复本地打包；指定 `OUTPUT` 时仍要求目标目录不存在。其他平台通过 targets 显式指定，版本仍写入 CLI 与技能清单。所有目标完成后才公布目录，失败清理临时产物。技能 ZIP 内容按路径排序，无时间戳波动。

## 冲突与恢复

`fail` 在写技能前停止，`skip` 保留同名目录（需存在 SKILL.md），`replace` 完整替换所选目录。非目录或符号链接形式的技能冲突一律拒绝，安装路径父目录的非标准链接也会拒绝，避免意外写入其他位置；用户指定项目根目录先规范化。

写入先暂存于目标 `.agents` 内，再逐目录重命名；原目录临时备份。可检测的提交失败会撤销本次新增目录并恢复原目录。恢复失败则保留备份并显示路径。成功后清除暂存与备份。安装器间通过 `.agents/.general-skills-install.lock` 排他；不防御安装期间其他程序主动篡改文件的竞态。

断电、强制终止不保证自动恢复。遇到遗留锁先确认没有安装程序运行，检查 `.agents/.general-skills-backup-*` 与 `.general-skills-stage-*`，需要时手动恢复原技能；核对数据后再移除锁和临时目录。不要在不明状态下删除备份。

项目级必须指定存在的目录，用户级使用当前用户主目录。安装器不删除未选技能、不迁移旧目录、不处理其他安装来源的重名。`--dry-run` 验证并预览，不创建目标目录。

## 验证边界

Go 测试覆盖五种场景、文件保持、冲突、预览、注入提交失败后的回滚、锁与路径保护、包损坏和按场景缺失引用。发布验证包括六个平台交叉编译、ZIP 校验和、本机交互安装及隔离用户安装。非本机操作系统仅完成编译和制品检查，尚未在 Windows/Linux 原生运行，也未验证 Codex 实际加载。
