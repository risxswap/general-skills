# 项目架构与技术栈约定

产品场景、运行平台、架构与技术选型由目标项目的 `AGENTS.md` 说明。先读取适用于当前目录的项目约定，以及它指向的架构说明；已明确的决定直接沿用。技能提供工作方法和技术参考，安装场景只选择技能，不替项目决定技术栈。

## 缺少定义时

- **已有项目**：先检查构建配置、依赖与锁文件、目录结构、启动和部署配置，以及当前任务相关的调用链与测试。用具体文件说明实际框架、模块边界、分层职责和部署形态，区分可验证事实、推断与未知。向用户概括现状，提出延续或调整的建议，沟通确认哪些约定应记录；不能仅凭目录名认定架构，也不能把历史实现自动定为未来规范。
- **新项目**：围绕当前需求引导用户选择产品场景、运行平台、架构、语言与框架、数据访问及必要基础设施。给出简明建议与取舍，只询问影响当前实施的选择；不预设 MVC、Spring Boot、Vue 3 或 TypeScript，也不要求一次决定所有未来依赖。
- **定义与代码冲突**：指出具体差异及影响，确认是记录过时、实现偏离还是正在迁移；保留适用的原约定，不擅自改文档迁就代码或迁移技术栈。

向用户说明这些决定将作为 `AGENTS.md` 的项目约定。沿用会话中已明确的选择，不重复确认；尚未确认的选型只作为建议。等待必要选择期间继续独立调查和验证，依赖该选择的实现待确认后再推进。资料缺失不妨碍只读诊断和审查，也不能据此判定实现违反某种未约定架构。

## 确认后记录

在获准写文件的范围内，补充适用的 `AGENTS.md`；不存在时创建，保留原有内容及目录作用域，不同时创建大小写不同的重复文件。只讨论或只审查时，在回复中提供建议段落，引导用户补充文件，保持原任务的写入边界。

按实际需要记录：架构与模块职责、技术栈与版本策略、数据库和持久层、前端产品场景、运行平台与组织方式、适用的编码规范，以及构建/测试配置和已有架构文档的位置。只写已确认内容，不生成空模板；能从配置读取的精确依赖版本引用配置位置，特殊版本限制与原因才写入约定。详细取舍沿用已有架构文档或 ADR，`AGENTS.md` 保留摘要与指针。

完成时说明已确认的约定、记录位置或待写入文本，以及仍影响当前任务的未决项。确认架构不等于授权重构整个项目。
